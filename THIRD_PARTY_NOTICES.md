## Source installations

The npm and uv lockfiles identify dependencies fetched when building or installing Weft. Their source and license files remain in the installed packages. The repository does not vendor these dependency implementations. User-imported icons are private installation data; importing them grants no artwork or trademark rights.

## Built frontend

Every production frontend build creates a `licenses/` directory containing:

| File | Contents |
| --- | --- |
| `LICENSE` | The original Weft license. |
| `NOTICE` | The required copyright notice and third-party exclusions. |
| `THIRD_PARTY_NOTICES.md` | This index. |
| `frontend-dependencies.md` | Full license texts generated by Vite from bundled JavaScript packages, including Lucide's ISC and Feather-derived MIT notices. |
| `rolldown.txt`, `rolldown-third-party.txt` | Rolldown and Rollup/esbuild-derived runtime helper notices. |
| `instrument-sans.txt` | Instrument Sans copyright and full SIL Open Font License, copied from `@fontsource-variable/instrument-sans`. |

Run `npm ci` and `npm run build` in `frontend/` to regenerate these files from the locked packages. Keep the entire `licenses/` directory with the built frontend. The build fails if a copied notice is missing. Review the emitted texts after dependency changes, including any new fonts or other assets that Vite's module inventory does not cover.

Rolldown injects runtime helpers that Vite's package inventory omits. Its own license is copied from the installed package. The supplementary text is retained verbatim in `frontend/notices/rolldown-third-party.txt` from [Rolldown 1.2.19](https://raw.githubusercontent.com/rolldown/rolldown/v1.2.19/THIRD-PARTY-LICENSE). The build requires that reviewed Rolldown version. After an upgrade, review and replace the supplementary text from the matching upstream version, then update the version check in `frontend/vite.config.ts`.

Plaid Link loads from Plaid's CDN only when a bank sign-in or repair starts. It is not included in this bundle. Provider service terms and access requirements are separate from the SDK licenses.

## Installed runtime

`./weft start` builds the frontend into `backend/app/static/` and runs the backend from the checkout. Notices stay in these locations:

| Location | Contents |
| --- | --- |
| `LICENSE`, `NOTICE`, `THIRD_PARTY_NOTICES.md` | Original Weft terms and this index, at the checkout root. |
| `backend/app/static/licenses/` | The frontend notices listed above. |
| `backend/.venv/lib/python3.*/site-packages/` | Python package licenses, vendor notices and available SBOMs, usually in each package's `.dist-info/licenses/` directory. Some packages place them elsewhere or omit them. Preserve these files, including Pillow's complete combined codec notices and certifi's source and MPL license. |

Python itself comes from the operating system or from `uv`'s managed Python builds, which carry their own license files.

## Before distributing prebuilt binaries

This index documents notice packaging. It does not certify a complete native-library inventory or source-delivery compliance for a prebuilt binary. Before publishing one, inspect the exact artifact and its platform-specific dependencies. Use upstream SBOMs and license files to assemble any missing embedded Rust, OpenSSL, libuv and other native notices. Resolve packages with missing license text, including nulltype's Apache-2.0 declaration. Check applicable source-availability obligations for covered libraries and operating-system components. Preserve upstream rights and document where recipients obtain the corresponding source.

Publishing a source checkout does not distribute the dependencies a user installs from it. Artwork, repository history, provider agreements and contribution permissions still require their own release checks.
